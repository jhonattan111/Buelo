## 🎯 O produto em uma frase

Buelo é uma **plataforma de geração de relatórios**, **self-hosted** (cada usuário roda a própria
instância, estilo **jsreport, mas em C#/QuestPDF**), consumida por **chamadas de API gated por key**.
O usuário autora relatórios de forma **declarativa (YAML)** — e, como modo avançado, em **C#**.

## 🧭 Como chegamos aqui (resumo da conversa)

Partimos dos 3 objetivos macro do usuário (editor fluido tipo IntelliSense, linguagem declarativa
YAML, validação de botões) e da visão de "hub de relatórios via API". Investigamos os dois repos,
descobrimos que a DSL declarativa já existiu e foi removida em abril (ARCHITECTURE.md), e
**re-justificamos o declarativo** sob a nova visão de hub. Definimos a arquitetura-alvo (dois
caminhos de autoria → modelo canônico → QuestPDF), resolvemos o que "HTML" significa, simplificamos
a segurança ao assumir o modelo self-hosted, ancoramos no jsreport, e escrevemos o **blueprint do
schema canônico**. Por fim, decidimos a persistência (EF Core, Postgres em prod) — restando só o
fork de onde guardar as definições.

## ✅ Decisões fechadas

1. **Direção declarativa** — revival de um modelo YAML, mas desenhado como *lowering* sobre um
   modelo canônico compartilhado (não a DSL antiga).
2. **Ambos primeira-classe** — autoria **declarativa E C#**. Reconciliados por um **modelo canônico
   `BueloDocument`** (IR) + ponte **"eject → C#"** (declarativo gradua para código).
3. **Motor declarativo interpretado** — schema → QuestPDF direto, **sem Roslyn**, sem codegen.
4. **"HTML" = bloco de conteúdo formatado** (Markdown lidera; HTML-subset secundário), transpilado
   para primitivas QuestPDF. **QuestPDF continua o motor** — NÃO trocar para Chromium. (QuestPDF não
   renderiza HTML nativo, por design.)
5. **Teto declarativo ≈ 95%** — layout é ~100% expressável; o limite é lógica/computação. Expressão
   **deliberadamente simples**; algoritmo pesado vai para **extension C#** (barato porque self-hosted).
6. **Modelo self-hosted** — cada um roda a própria instância → **sem sandbox**, **sem multi-tenant**.
   Segurança = **API key (Bearer)** gateando os endpoints + `/ping` público + auth **opt-in**.
   Código roda sem sandbox porque quem tem key é confiável.
7. **Referência: jsreport em C#/QuestPDF.** Arquitetura **engine × recipe × extension**:
   - *Recipe* (saída) → `OutputRendererRegistry` (PdfRenderer/QuestPDF, ExcelRenderer/ClosedXML) **já existe**.
   - *Engine* (autoria→documento) → interpretador declarativo + compilador C# (formalizar como registry).
   - *Extension* → plugins (helpers, validadores, recipes) — lar do código custom self-hosted.
   - Vantagem sobre jsreport: o IR é um **layout tipado** (`BueloDocument`), não HTML → sem armadilhas de paginação.
8. **Sistema de módulos** (o moat): `styles` (classes nomeadas + `extends`), `component`
   (composição + `params` + `slots`, substituindo a herança da `LayoutPadrao`), `formats` (máscaras),
   `lib` (expressões puras nomeadas), `validator`, `theme`. Resolução local → global. Pin opcional.
9. **Funções/validadores:** stdlib do motor para o universal com lógica (cnpj/cpf/moeda/data); o
   usuário importa só **dado declarativo**. Validadores em **3 degraus**: declarativo (mask/regex/checksum)
   → expressão pura → extension C#.
10. **Persistência** — EF Core plugável: **SQLite** (dev/self-host leve), **PostgreSQL** (default de
    prod, por concorrência de escrita + multi-nó, não por volume). Dois domínios: **definições**
    (documento, versionado) vs **dados operacionais** (logs de emissão, login/auditoria, render
    history, parâmetros → Postgres). Config de instância (conn string, keys, auth) em **env/secrets**.
    Ver [blueprint §13](blueprint-schema-canonico.md).
11. **Charts → v2** (depois que os reports básicos funcionarem).
12. **Sprint de hardening encolheu** (com o modelo self-hosted): sobra persistência durável + cache de
    assembly + timeouts + token opcional. Caiu: sandbox, multi-tenant, rate-limit. → **A fatia vertical
    declarativa virou a prioridade**, não o hardening.
