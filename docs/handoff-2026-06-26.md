## 🎯 The product in one sentence

Buelo is a **report generation platform**, **self-hosted** (each user runs their own
instance, jsreport-style **but in C#/QuestPDF**), consumed via **key-gated API calls**.
The user authors reports **declaratively (YAML)** — and, as an advanced mode, in **C#**.

## 🧭 How we got here (conversation summary)

We started from the user's 3 macro objectives (fluid IntelliSense-like editor, declarative
YAML language, button validation) and the "report hub via API" vision. We investigated the two repos,
discovered that the declarative DSL once existed and was removed in April (ARCHITECTURE.md), and
**re-justified the declarative approach** under the new hub vision. We defined the target architecture (two
authoring paths → canonical model → QuestPDF), resolved what "HTML" means, simplified
security by assuming the self-hosted model, anchored on jsreport, and wrote the **canonical
schema blueprint**. Finally, we decided on persistence (EF Core, Postgres in prod) — leaving only the
fork of where to store the definitions.

## ✅ Closed decisions

1. **Declarative direction** — revival of a YAML model, but designed as *lowering* over a
   shared canonical model (not the old DSL).
2. **Both first-class** — **declarative AND C#** authoring. Reconciled by a **canonical
   `BueloDocument` model** (IR) + **"eject → C#"** bridge (declarative graduates to code).
3. **Interpreted declarative engine** — schema → QuestPDF directly, **no Roslyn**, no codegen.
4. **"HTML" = formatted content block** (Markdown leads; HTML-subset secondary), transpiled
   to QuestPDF primitives. **QuestPDF stays the engine** — do NOT switch to Chromium. (QuestPDF does not
   render native HTML, by design.)
5. **Declarative ceiling ≈ 95%** — layout is ~100% expressible; the limit is logic/computation. Expressions
   **deliberately simple**; heavy algorithms go to a **C# extension** (cheap because self-hosted).
6. **Self-hosted model** — everyone runs their own instance → **no sandbox**, **no multi-tenant**.
   Security = **API key (Bearer)** gating the endpoints + public `/ping` + **opt-in** auth.
   Code runs without a sandbox because whoever holds the key is trusted.
7. **Reference: jsreport in C#/QuestPDF.** **engine × recipe × extension** architecture:
   - *Recipe* (output) → `OutputRendererRegistry` (PdfRenderer/QuestPDF, ExcelRenderer/ClosedXML) **already exists**.
   - *Engine* (authoring→document) → declarative interpreter + C# compiler (formalize as a registry).
   - *Extension* → plugins (helpers, validators, recipes) — home of the self-hosted custom code.
   - Advantage over jsreport: the IR is a **typed layout** (`BueloDocument`), not HTML → no pagination pitfalls.
8. **Module system** (the moat): `styles` (named classes + `extends`), `component`
   (composition + `params` + `slots`, replacing `LayoutPadrao` inheritance), `formats` (masks),
   `lib` (named pure expressions), `validator`, `theme`. Resolution local → global. Optional pin.
9. **Functions/validators:** engine stdlib for the universal-with-logic (cnpj/cpf/moeda/data); the
   user imports only **declarative data**. Validators in **3 steps**: declarative (mask/regex/checksum)
   → pure expression → C# extension.
10. **Persistence** — pluggable EF Core: **SQLite** (dev/lightweight self-host), **PostgreSQL** (prod
    default, for write concurrency + multi-node, not for volume). Two domains: **definitions**
    (document, versioned) vs **operational data** (issuance logs, login/audit, render
    history, parameters → Postgres). Instance config (conn string, keys, auth) in **env/secrets**.
    See [blueprint §13](blueprint-schema-canonico.md).
11. **Charts → v2** (after the basic reports work).
12. **Hardening sprint shrank** (with the self-hosted model): what remains is durable persistence + assembly
    cache + timeouts + optional token. Dropped: sandbox, multi-tenant, rate-limit. → **The declarative
    vertical slice became the priority**, not hardening.
