### O que existe (resumão)
- **Engine declarativo** YAML→IR(`BueloDocument`)→QuestPDF, paralelo ao C#/Roslyn. Parser, motor de
  expressão (stdlib + agregação), blocos (text/markdown/**html**/table/row/column/card/image/spacer/
  divider/pageBreak), bandas, módulos (styles/component/theme/formats/lib/validator).
- **Recipes:** PDF (QuestPDF) **e Excel** (ClosedXML) a partir do mesmo IR — `?format=excel`.
- **Validators** 3 degraus + **`validate:` no render** (gate fail-fast → 400) + `POST api/validate-data`.
- **Persistência:** `IDefinitionStore` (fs/InMemory) p/ definições; EF Core operacional (SQLite/Postgres)
  p/ histórico de render. Startup **migration-ready** (`Migrate()` se houver migrations, senão `EnsureCreated()`).
- **Eject** C# (round-trip validado). **JSON Schema** por kind (`api/schemas`) + **Monaco** (monaco-yaml).
- **Hardening:** cache de assembly Roslyn, token Bearer opt-in + `/ping`, **render-timeout** (503).
- **Exemplos:** `Buelo.Api/definitions/` (hello/invoice/colaboradores + módulos + dados mock).
- **Verificado ao vivo** (sessão 28/06): todos os endpoints + EF logando no SQLite + front servindo.

## ⏳ Pendências (continuar daqui)

1. **Migrations EF — bloqueado por conflito de dependência.** A app já é migration-ready, mas gerar os
   arquivos com `dotnet ef migrations add` falha: **EF Design 10.0.9 → Roslyn (CodeAnalysis) 5.0.0**, que
   conflita com o **5.3.0** que o `Buelo.Engine` usa (NU1107). Opções: (a) projeto de tooling isolado p/
   migrations; (b) alinhar versões do Roslyn; (c) seguir com `EnsureCreated` (funciona p/ self-host). O
   `dotnet-ef 10.0.9` já está instalado global. Comando alvo:
   `dotnet ef migrations add InitialCreate --project Buelo.Engine --startup-project Buelo.Api -o Persistence/Migrations`.
2. **Front — `vite` preso no major 6.** vite 7/8 quebram o `vite-plugin-monaco-editor@1.1.0` patchado
   (`MODULE_NOT_FOUND` em workerMiddleware). Trocar/atualizar esse plugin antes de subir o vite.
3. **Front — `lucide-vue-next` deprecado** → migrar imports p/ `@lucide/vue` (refactor mecânico em vários
   componentes).
4. **Verificação ao vivo do autocomplete YAML no browser** — o bundle tem o yaml worker e os schemas, mas
   só dá pra confirmar o autocomplete/validação abrindo o editor (`pnpm dev` + criar `algo.report.yml`).
5. Limitações v1 menores: width `%` ≈ peso relativo; image só base64/arquivo local; palette do theme não
   resolve nomes de cor; eject degrada image p/ placeholder; Excel achata layout (tabela vira planilha).
