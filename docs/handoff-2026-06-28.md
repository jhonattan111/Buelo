## ✅ Decisions closed in this session (06/28)

1. **DEFINITIONS persistence — pluggable `ITemplateStore` (already exists in the code).** Default **fs-store**
   (`.yml` files, git for free), with SQLite/Postgres providers available through the same interface.
   Not an irreversible decision: the abstraction is already in the code (`FileSystemTemplateStore`,
   `FileSystemWorkspaceStore`, `InMemoryTemplateStore`).
2. **OPERATIONAL persistence — EF Core pluggable via config.** **SQLite default in dev** (zero infra,
   starts without a container — meets the desire to streamline dev), **PostgreSQL default in prod** (write
   concurrency + multi-node). Same entity model; provider-agnostic schema; per-provider migrations
   (known caveat). This is **hardening — comes after the vertical slice**.
   - **Different axes (the insight):** definitions use a custom interface because a backend (fs/git) is not a
     database; operational uses EF Core directly because it's all relational and EF is already the abstraction.
3. **Serialization — YAML only** for definitions. Data stays JSON (comes from the API). One parser:
   **YamlDotNet**. (Updates blueprint §12.1, which previously suggested YAML+JSON.)

> Backend state confirmed by reading the code (06/28): **there is no EF Core nor any database today** — the
> persistence is already file-on-disk behind `ITemplateStore`/`IWorkspaceStore`/`IGlobalArtefactStore`.

## 🛣️ Vertical slice plan (implementation order)

Goal: the `report` "Hello {{ data.name }}" renders to PDF end to end. Then, the §5 invoice.

1. **IR `BueloDocument` (minimal)** — `Meta`, `Page{header,content,footer}`, base `Node`, `TextNode{runs}`,
   `Run{text,style}`, resolved `Style`. (blueprint §9) Location: `Buelo.Contracts` or new `Buelo.Engine/Ir`.
2. **YAML parser** — add `YamlDotNet` to `Buelo.Engine`; read the `.yml` into a declarative AST model
   (§3 anatomy — `kind`, `meta`, `content`, blocks).
3. **Interpreter (lowering)** — AST + JSON data → `BueloDocument`. v1: resolves `{{ data.x }}` and literals.
   No `forEach`/`groupBy` yet (they come in with the §5 table).
4. **Composer `BueloDocument` → QuestPDF** — new component that walks the IR and composes the QuestPDF
   `IDocument`; emits PDF via the existing bytes path. Reuses `PageSettings`.
5. **Wiring + endpoint** — `meta.engine: declarative` path in render (new endpoint
   `POST api/report/render-declarative` or a flag on the existing one). Reads the YAML definition from the fs-store.
6. **End-to-end test** — xUnit in `Buelo.Tests`: YAML "Hello {{data.name}}" + `{name:"..."}` → non-empty PDF.

After the slice: table/`forEach`/`groupBy` (§5) → JSON Schema for Monaco autocomplete (objective #1) →
hardening (operational EF Core, assembly cache, timeouts, token).
