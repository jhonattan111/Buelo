## ✅ Decisões fechadas nesta sessão (28/06)

1. **Persistência das DEFINIÇÕES — `ITemplateStore` plugável (já existe no código).** Default **fs-store**
   (arquivos `.yml`, git de graça), com providers SQLite/Postgres disponíveis pela mesma interface.
   Não é decisão irreversível: a abstração já está no código (`FileSystemTemplateStore`,
   `FileSystemWorkspaceStore`, `InMemoryTemplateStore`).
2. **Persistência OPERACIONAL — EF Core plugável por config.** **SQLite default no dev** (zero infra,
   sobe sem container — atende a vontade de agilizar o dev), **PostgreSQL default em prod** (concorrência
   de escrita + multi-nó). Mesmo modelo de entidades; schema provider-agnóstico; migrations por-provider
   (ressalva conhecida). Isso é **hardening — vem depois da fatia vertical**.
   - **Eixos diferentes (o insight):** definições usam interface custom porque um backend (fs/git) não é
     banco; operacional usa EF Core direto porque é tudo relacional e o EF já é a abstração.
3. **Serialização — YAML only** para definições. Dados continuam JSON (vêm da API). Um parser:
   **YamlDotNet**. (Atualiza o blueprint §12.1, que antes sugeria YAML+JSON.)

> Estado do backend confirmado lendo o código (28/06): **não há EF Core nem banco nenhum hoje** — a
> persistência já é arquivo-em-disco atrás de `ITemplateStore`/`IWorkspaceStore`/`IGlobalArtefactStore`.

## 🛣️ Plano da fatia vertical (ordem de implementação)

Meta: o `report` "Hello {{ data.name }}" renderiza em PDF de ponta a ponta. Depois, a fatura do §5.

1. **IR `BueloDocument` (mínimo)** — `Meta`, `Page{header,content,footer}`, `Node` base, `TextNode{runs}`,
   `Run{text,style}`, `Style` resolvido. (blueprint §9) Local: `Buelo.Contracts` ou novo `Buelo.Engine/Ir`.
2. **Parser YAML** — adiciona `YamlDotNet` ao `Buelo.Engine`; lê o `.yml` num modelo de AST declarativo
   (anatomia do §3 — `kind`, `meta`, `content`, blocos).
3. **Interpretador (lowering)** — AST + dados JSON → `BueloDocument`. v1: resolve `{{ data.x }}` e literais.
   Sem `forEach`/`groupBy` ainda (entram com a tabela do §5).
4. **Composer `BueloDocument` → QuestPDF** — novo componente que percorre o IR e compõe o `IDocument`
   QuestPDF; emite PDF via o caminho de bytes já existente. Reusa `PageSettings`.
5. **Wiring + endpoint** — caminho `meta.engine: declarative` no render (novo endpoint
   `POST api/report/render-declarative` ou flag no existente). Lê a definição YAML do fs-store.
6. **Teste de ponta a ponta** — xUnit em `Buelo.Tests`: YAML "Hello {{data.name}}" + `{name:"..."}` → PDF não-vazio.

Depois da fatia: tabela/`forEach`/`groupBy` (§5) → JSON Schema p/ autocomplete Monaco (objetivo #1) →
hardening (EF Core operacional, cache de assembly, timeouts, token).
